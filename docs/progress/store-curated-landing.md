# Store curated landing page

- **Status:** done
- **Date:** 2026-08-04
- **Specs touched:** `APP_STORE.md`

The box's app store landing was much thinner than the control plane's own store surface: a curated `home.yml` (a spotlight app + ordered category groups) was published on the control-plane snapshot but never carried onto the box, so the box's landing was pills + a flat Featured strip only, with no spotlight banner and no packed category rows.

## What was done

### `internal/catalog` (box)

- `wire.go` — added `wireHomePage` / `wireHomeGroup`, byte-faithful mirrors of the control plane's own `HomePage` / `HomeGroup` shape, and a `Home wireHomePage` field on `catalogFile`. Confirmed `indexDigest` hashes `f.Apps` only, so this addition does not touch the box's index-digest contract with the control plane.
- `catalog.go` — extended `Home` with `Spotlight *Entry` and `Groups []HomeGroupView` (new type, mirroring the control plane's own `HomeGroupView`), keeping `Categories`/`Featured` as-is. Added a `home() (*Entry, []HomeGroupView, error)` method to the `source` interface, alongside the existing `featured()`, since neither can be derived from `List()`.
- `remote.go` — `snapshot` now carries the parsed `wireHomePage`; `remoteSource.home()` projects it filtered to the box's environment: an app the block names that isn't advertised on this surface drops the spotlight to nil or is skipped within its group, and a group left with no advertised apps is dropped entirely — mirroring the control plane's own `Home` projection semantics field-for-field.
- `disk.go` — `diskSource.home()` returns `nil, nil, nil` (no curation on a bare manifest tree); unchanged behavior otherwise.
- Tests: `segmented_test.go` gained `TestHomeProjectsSpotlightAndGroups` (spotlight/group projection + per-environment filtering, including a group that empties out entirely) and `TestHomeNoBlockYieldsNoSpotlightOrGroups` (a snapshot with no home block yields neither, with categories/featured unaffected), plus the `homeFixture`/`makeSnapshotHome`/`newFakeCPHome`/`syncedCatalogWithHome` fixtures they build on.
- Regenerated `api/openapi.json` / `api/openapi.yaml` (`make openapi`) so the `Home` schema carries `spotlight`/`groups` and a new `HomeGroupView` schema exists.

### `web-ui` (box dashboard)

- `src/api.ts` — regenerated `src/generated/openapi.ts` (`npm run gen:api`) and added the `HomeGroupView` type alias.
- `src/lib/storeLayout.ts` (new) — `packRows`, a faithful port of the control plane's own row-packing algorithm: groups walk in authored order, pulling forward the first later group that fits the remaining row width (4 columns), so a group that can't be paired stands alone. Also `groupSpan`/`groupCols`, which map a group's app count to a fixed, written-out set of Tailwind `sm:col-span-N` / `sm:grid-cols-N` classes (not interpolated, since Tailwind's scanner can't see interpolated class names — same reasoning the control plane's own layout code follows). Also `categoryLabel`, a display-only stopgap (hyphens to spaces, e.g. `developer-tools` → "developer tools") mirroring the control plane's own label formatting — without it, the box's group headings, category-page heading, and pills would render the catalog's only hyphenated category id (`developer-tools`) as "Developer-tools" while the control plane's own store surface renders "developer tools" for the same id, the exact cross-surface divergence this feature is closing elsewhere. No test file: `web-ui` has no test runner configured (`package.json` has no `test` script, no vitest), so this stays plain, readable code rather than adding a first-of-its-kind test harness for a couple of helpers.
- `src/components/StoreSpotlight.vue` (new) — the spotlight banner: icon tile, "Spotlight" eyebrow, name, tagline, the whole card a `RouterLink` to `/store/:id`. Styled with the box's semantic tokens (`border-border`, `bg-card`, `text-accent`, `text-muted-foreground`), not raw palette classes.
- `src/components/StoreAppCard.vue` — added the tagline (`short_description`) as a second, truncated line under the name; widened the icon from `size-1/2` to `size-3/5`. Kept the existing `icon_glyph` fallback and broken-icon guard unchanged.
- `src/views/StoreView.vue` — landing (`mode === "home"`) now renders, in order: the spotlight banner, then the authored category groups packed via `packRows` (each row its own `sm:grid-cols-4` grid, each group a `flex flex-col` sized by `groupSpan`/`groupCols`). Fallback chain preserved: authored home (spotlight/groups) → the existing flat Featured row (now shown on the landing only when nothing is authored) → the existing "Pick a category or search" line. Category and search modes are unchanged except for the grid-width change below. Every store grid (`sm:grid-cols-4 lg:grid-cols-6` → `sm:grid-cols-3 lg:grid-cols-4`) is now wider per-card: the featured row, the category grid, the search grid, and the new group rows all match. Group headings, the category-page heading, and the category pills all render through `categoryLabel` now, so the three agree with each other.
- Two review follow-ups, mirroring how the control plane's own store surface renders pills and category grids more closely: (1) the curated Featured row no longer leaks onto a category view — it is landing-only (the no-authored-home fallback), matching the control plane's own category rendering, which shows only the heading + grid, never a featured row; `catalog.Category` still carries `Featured` on the wire (parity with the control plane's own `Category` shape), the box UI just stops rendering it, so the doc comment on `catalog.Category` was corrected to say so. (2) dropped the `"all"` pill: pills are the real categories only (the control plane's own posture — "the recommended landing is the default view, not a pill"); the landing sentinel is `activeCategory.value === "recommended"` now (checked against the catalog's category ids: none of the eight is `recommended`, so no collision), clicking the already-active pill toggles back to the landing (`pillActive`/`selectCategory`), and the category empty-state's button was reworded from "Back to all" to "Back to recommended" since there is no "all" to go back to.

### `dev/mkcatalog` (dev seed tool — a third mirror of the wire shape, also updated)

`dev/mkcatalog/main.go` re-declares the `catalogFile`/`app` wire shapes independently of `internal/catalog/wire.go` (by design — it has no import path back into `internal/catalog`'s unexported types) and its header comment says to keep it in sync. It now does:

- mirrors `wireHomePage`/`wireHomeGroup` alongside the existing shapes, field order and tags matching `wire.go`.
- `-pkg` is now repeatable (a `flag.Value` collecting into a slice) instead of taking exactly one package — a curated landing needs several apps in one snapshot. A single `-pkg` (both existing call sites: `make seed-catalog APP=<id>` / `make dev-app APP=<id>`, and `dev/test-qemu/bootstrap.sh`'s single-app whoami seed) behaves exactly as before.
- new `-home <path/to/home.yml>` flag parses a curated `home.yml` and emits it as the snapshot's `home` block; omitted ⇒ no home block (unchanged default). An id named in `home.yml` that wasn't also passed via `-pkg` is a fatal error (`mkcatalog: home … names app …, which was not seeded with -pkg`), not a silently-dropped slot.
- `make seed-catalog` now accepts `APPS="<id> <id> ..."` (space-separated) alongside the existing `APP=<id>`, plus an optional `HOMEFILE=<path>` (named to avoid colliding with the shell's own `$HOME`). `make dev-app` and `make help` document the new form; `docs/dev/authoring-apps-with-an-agent.md` gets a pointer to it from the existing single-app boot step.

**Verified against a real running brain, not just `go test`:** seeded a snapshot with `make seed-catalog APPS="immich hermes-agent openclaw actual-budget memos jellyfin nextcloud paperless-ngx docuseal twenty plane kimai gitea nocodb jupyter flipt vaultwarden" HOMEFILE=<path>/home.yml STORE=<path>` (all 17 apps the curated `home.yml` names, from a real store curation checkout), started the fake host-agent + a native brain against that cache dir with `MALMO_CATALOG_URL` pointed at an inert address (so the background sync can't overwrite the seed), bootstrapped an admin via `POST /api/v1/setup`, and called `GET /api/v1/catalog/home` with the session cookie: the response carried `spotlight.id: "immich"` and all seven authored groups (`ai`, `personal`, `media`, `documents`, `productivity`, `developer-tools`, `security`) with their apps in authored order. Also verified the fatal-error path: a `-home` file naming an app not passed via `-pkg` exits 1 with the intended message rather than silently dropping the slot.

**Also verified the pill/featured-row fix (the second review round) in an actual browser**, not just by reading the code: the same seeded snapshot, brain, and fake host-agent, plus `npm run dev` (Vite) fronting them, driven with a headless Chrome via Playwright. Confirmed: the landing shows the spotlight banner + packed groups with no "Featured" heading anywhere on the page; the pill row reads `Ai, Developer Tools, Documents, Media, Personal, Productivity, Security` with no "All" pill; clicking "Developer Tools" shows only that category's grid (no Featured, no Spotlight); clicking it again returns to the landing (the pill's class list confirmed inactive, not just visually); searching while a pill is active shows only the search results (no Featured), and clearing the search returns to the landing, not back to the pill.

## Known gaps & deviations

- No unit test for `packRows`/`groupSpan`/`groupCols`/`categoryLabel` in `web-ui` — the repo has no test runner (`vitest`, `jest`, etc.) configured for the frontend at all, appliance- or box-wide; adding one for a few small helpers felt like scope creep on a UI feature change. `make check-web` (typecheck + production build) is the only frontend gate today.
- The catalog's authored category `label:` field is deliberately not on the wire (a separate follow-up change); the box's `categoryLabel` is a display-only stopgap (hyphens to spaces) that at least keeps the box and the control plane's own store surface agreeing on the same id, rather than a real localized/authored label.
- `dev/mkcatalog`'s home-vs-seeded-apps validation only checks that every id `home.yml` names was also passed via `-pkg` — it does not validate that a group's `category:` is one of the catalog's known category ids (that check lives in the store curation source's own publish-time tooling, not in this local dev tool).
